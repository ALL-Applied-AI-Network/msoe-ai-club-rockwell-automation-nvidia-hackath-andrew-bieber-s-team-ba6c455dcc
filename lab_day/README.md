# Lab Day Runbook: Sat Oct 31

**How the real cell works:** you don't upload a script to the robot. Your computer runs our policy
(`physical-client/policy.py`). The cell's server sends it camera images and the arm's pose, the policy sends back
the next move, and the cell carries it out within its own safety limits. You start the client with
`uv run run.py` (or `bash lab_day.sh run …`), leave it running, and the operator starts each rollout.

**How you're scored:** each rollout passes only if the task is done **with no operator intervention and no
fault**. Ranking is by success rate, with fewer faults breaking ties. A rollout the operator has to rescue counts as
a fail, so a small reliable task beats an ambitious one.

## 4. Plan B only: mount and measure the printed fingers

1. Fit the **coupon** on one jaw first. If the holes don't line up or it rocks, stop and use Plan A.
2. Bolt both bodies through the jaw holes onto the outside face of each jaw tongue (metal nuts, no plastic threads).
   Add the 1 mm pads to the bottom 32 mm of each rail.
3. **Calipers, gripper closed:** narrow gap ≈ **5.2 mm**, wide gap ≈ **18 mm**. **Open:** ≈ 17.2 mm and ≈ 30 mm.
   Off by more than ~0.5 mm → fix the pads before continuing.
4. **Fingertip offset.** The controller's tool point (UTOOL1) was set for the stock fingers, so the printed tips may
   reach lower or higher than the robot thinks. While the arm holds during a preview:
   - Read `tcp_pose_uf0_mm` from the `preview_only` line in the terminal. The 3rd number is Z, in mm.
   - Measure the real gap from the **narrow-zone fingertip** to the table, in mm.
   - `offset_mm = (Z + 335.1) − measured_gap`. Positive means the printed tips reach further down.
   - Example: Z = −35.1 means the robot thinks the tips are 300 mm up. If you measure 288 mm, offset = +12 mm.
   - If |offset| > 25 mm or you're unsure, ask the operator to re-teach UTOOL1 instead, and leave the offset at 0.
5. Edit `sort_config.py` (nano/vim):

   ```python
   DUAL_ZONE_PRIMARY_OFFSET_TCP_M = (0.0, 0.0, 0.012)   # your offset_mm / 1000
   DUAL_ZONE_MOUNT_CONFIRMED = True    # fingers mounted, gaps checked, offset measured
   DUAL_ZONE_OBJECTS_CONFIRMED = True  # objects are M6x30 screws, 9–16 mm cubes, 27 x 203 mm vials
   DUAL_ZONE_LAYOUT_CONFIRMED = True   # operator agreed to the destination zones
   ```

   Leave `DUAL_ZONE_CAP_NARROW_END_UP = False`. Caps stay off today.
6. Run a fresh preview (step 3) with `dual_zone_v2` to check the setup still holds.

## If something goes wrong

| Symptom | Fix |
|---|---|
| `WARNING: no .request.json here` | Wrong folder, or the request file is missing. See section 1c |
| `Missing SAM interpreter` | `export SORT_SAM_PYTHON="$HOME/venvs/sam2-check/bin/python"`, inside the GPU session |
| `uv: command not found` or a Snap permission error | `export PATH="$HOME/.local/physical-uv/bin:$PATH"` (needed again in every new shell) |
| Status not approved / client waits forever | Ask the operator or organizers on Slack. Don't submit a second request |
| `Set measured scan/drop poses …` halt | `PHYSICAL_POSES_CONFIRMED` is still False |
| Halt about mount/objects/layout | Plan B confirmations in step 4.5 aren't all True |
| Objects detected but none attempted | Outside the pickup area, the wrong type for the profile, or blocked by a neighbour. Check `targets.json` |
| Screw grabbed off-centre or crooked | Known Oct 22 failure. Log it, keep going, and mention it in the video's limitations |
